Capítulo 2.1

Primeiro Script, print() e Output

Transforme texto em instruções executadas pelo servidor, uma linha de cada vez.

Objetivos e pré-requisitos

  • Criar um Script no local recomendado para código do servidor.
  • Distinguir comentário, instrução, log e erro.
  • Ler ordem, origem e linha no Output.
  • Iniciar o Projeto 2 com uma mudança observável no começo do teste.

Pré-requisitos: 1.1, 1.2 e a versão final da Primeira sala.

Vocabulário novo

Código
Texto escrito em uma linguagem formal para descrever instruções.
Luau
Linguagem usada nos scripts Roblox, derivada de Lua 5.1 e ampliada pela Roblox.
Script
Instance que guarda código executável. Neste capítulo será configurada para servidor.
Função
Ação nomeada que pode ser chamada; por enquanto você apenas usará print().
Comentário
Texto iniciado por -- para humanos; não é executado.
Log
Mensagem registrada para observar o que ocorreu.

Modelo mental: uma receita lida de cima para baixo

Quando o servidor inicia o Script, ele lê instruções sequencialmente. print() recebe um texto entre parênteses e o envia ao Output. Aspas delimitam o texto; parênteses delimitam o que a função recebe.

Valores, variáveis, const e tipos básicos

Dê nomes claros aos dados para que o código consiga guardá-los, consultá-los e alterá-los.

Objetivos e vocabulário

Pré-requisito: 2.1.

  • Representar texto, número, verdadeiro/falso e ausência.
  • Criar variáveis locais e constantes nativas.
  • Usar typeof() para observar o tipo em runtime.
Valor
Dado concreto, como 25 ou "Sala".

Nome que referencia um valor e pode receber outro.

local limita o nome ao Script/bloco. const, novidade atual do Luau, também cria um nome local, mas impede reatribuição. A convenção LOUD_SNAKE_CASE torna constantes reconhecíveis.

Constante não congela tudo

Se uma const referencia uma tabela, o nome não pode apontar para outra tabela, mas o conteúdo ainda pode mudar. table.freeze() será apresentado em 2.7.

Capítulo 2.3

Operadores, expressões e conversões

Combine valores para calcular, comparar e produzir novas informações.

Objetivos, pré-requisito e termos

Pré-requisito: 2.2.

  • Usar operadores aritméticos, relacionais e lógicos.
  • Distinguir atribuição = de comparação ==.
  • Combinar texto por interpolação e converter explicitamente.
Operador
Símbolo ou palavra que realiza uma operação.
Expressão
Trecho que produz um valor.
Precedência
Ordem em que operações são avaliadas.
Conversão
Criação de um valor de outro tipo de forma explícita.

Famílias essenciais

Aritmética: + - * / // % ^. Comparação: == ~= < <= > >=. Lógica: and or not. Parênteses tornam a intenção visível. Em Luau, somente false e nil são falsos; zero e string vazia são verdadeiros.

Interpolação Luau

Crases permitem inserir expressões em chaves: `Pontuação: {pontuacao}`. É mais legível que muitas concatenações com ...

Capítulo 2.4

Condições, decisões e saídas antecipadas

Faça o programa escolher um caminho com regras que podem ser explicadas e testadas.

Base do capítulo

Pré-requisito: 2.3.

  • Escrever if, elseif e else.
  • Ordenar condições da mais específica para a alternativa geral.
  • Combinar condições com and, or e not.
Condição
Expressão avaliada para decidir um caminho.
Bloco
Conjunto de instruções delimitado por palavras como then e end.
Guard clause
Verificação que encerra cedo quando um requisito falha. Será codificada com funções em 2.6.

Uma cadeia escolhe somente um ramo

Luau testa de cima para baixo, executa o primeiro ramo verdadeiro e ignora os demais. Não escreva == true quando o valor já é boolean; if temChave then é direto.

Zero não é falso em Luau

0 e "" contam como verdadeiros. Compare números explicitamente, por exemplo moedas > 0.

Prática guiada

Decida se a porta pode abrir

Script
RegraDaPorta
Caminho

RegraDaPorta.server.luauScript · servidor
local temChave = true
local nivelDoJogador = 3
const NIVEL_NECESSARIO = 2

if not temChave then
	print("Acesso negado: falta a chave.")
elseif nivelDoJogador < NIVEL_NECESSARIO then
	print("Acesso negado: nível insuficiente.")
else
	print("Acesso permitido: a porta pode abrir.")
end

O primeiro ramo trata a ausência da chave. O segundo só é testado se há chave. O else representa o caso em que todos os requisitos foram satisfeitos.

  1. Teste true/3: permitido.
  2. Teste false/3: falta chave.
  3. Teste true/1: nível insuficiente.
  4. Antes de executar cada caso, escreva sua previsão.

Erro comum: vários if separados podem imprimir mensagens contraditórias. Use uma cadeia quando os resultados são mutuamente exclusivos. Para reiniciar, restaure true e 3.

Capítulo 2.5

Laços, repetição segura e tempo

Repita uma instrução com limite, condição de término e espaço para a Engine trabalhar.

Objetivos e termos

Pré-requisito: 2.4.

  • Usar for quando a quantidade é conhecida.
  • Usar while somente com condição que muda.
  • Encerrar com break e ceder tempo com task.wait().
Laço
Bloco que pode executar repetidamente.
Iteração
Uma passagem pelo bloco.
Condição de término
Regra que torna a repetição finita.
Scheduler
Sistema que coordena quando tarefas de código recebem tempo de execução.
Laço infinito pode travar a sessão

Nunca escreva while true do sem compreender espera e saída. Prefira limites explícitos. task.wait() não corrige uma regra que jamais termina.

Prática guiada

Conte checkpoints e execute um cronômetro finito

Script
RepeticoesSeguras
Caminho

Contexto

RepeticoesSeguras.server.luauScript · servidor
const TOTAL_CHECKPOINTS = 3

for numeroCheckpoint = 1, TOTAL_CHECKPOINTS do
	print(`Verificando checkpoint {numeroCheckpoint}`)
end

local tempoRestante = 3

while tempoRestante > 0 do
	print(`Tempo restante: {tempoRestante}`)
	task.wait(1)
	tempoRestante -= 1
end

print("Cronômetro encerrado com segurança.")

O for controla início, fim e passo. No while, a condição é testada antes de cada iteração; o contador diminui e eventualmente chega a zero. task.wait(1) agenda a continuação depois de aproximadamente um segundo — não é cronômetro de alta precisão.

  1. Preveja as sete mensagens e execute.
  2. Troque o total para 5; confirme duas novas iterações.
  3. Troque o cronômetro para 2 e use break após o primeiro print somente como experimento; restaure depois.

Se o Output não parar: use Stop e procure uma condição que não muda. Não use pcall nem esconda o erro. Para reiniciar, restaure os limites 3.

Prática guiada

Separe a regra de recompensa

Script
FuncoesDaSala
Caminho

Contexto

FuncoesDaSala.server.luauScript · servidor
const RECOMPENSA_MAXIMA = 100

local function valorValido(valor)
	return valor >= 0 and valor <= RECOMPENSA_MAXIMA
end

local function calcularRecompensa(base, obstaculos)
	local total = base + (obstaculos * 5)

	if not valorValido(total) then
		return 0
	end

	return total
end

local function mostrarResultado(nomeDaSala, recompensa)
	print(`{nomeDaSala}: {recompensa} moedas`)
end

local recompensa = calcularRecompensa(20, 3)
mostrarResultado("Primeira Sala", recompensa)

valorValido responde com boolean. calcularRecompensa usa dois parâmetros e guarda uma variável local. A verificação com retorno antecipado é a guard clause anunciada em 2.4: uma entrada fora do limite termina com 0 antes de alcançar o retorno normal.

  1. Crie o Script, use RunContext Server e execute. O Output deve mostrar 35 moedas.
  2. Troque a base para 95; o cálculo vira 110, falha na validação e retorna 0.
  3. Adicione uma segunda chamada com base 10 e 2 obstáculos. Guarde e mostre o retorno.

Se aparecer nil: confira quantidade e ordem dos argumentos e se a função possui return. Para reiniciar, restaure a chamada final. O Output deve ficar sem erros.

Objetivos e vocabulário

Pré-requisito: 2.6.

  • Criar uma lista indexada a partir de 1.
  • Criar um dicionário acessado por chave.
  • Percorrer tabelas e compreender cópia rasa e congelamento.
Tabela
Estrutura Luau que associa chaves a valores.
Array
Tabela usada como sequência, normalmente com índices 1, 2, 3… sem buracos.
Dicionário
Tabela cujas chaves descrevem os valores.

Capítulo 2.8

Escopo, nil, erros e diagnóstico

Leia a evidência, encontre a primeira causa e corrija o menor trecho responsável.

Objetivos e termos

Pré-requisitos: 2.1–2.7.

  • Explicar onde um nome local existe.
  • Tratar nil antes de uma operação que exige valor.
  • Usar Output, número da linha e Script Analysis para diagnosticar.
Escopo
Região do código em que um nome pode ser acessado.
Erro de execução
Falha ocorrida enquanto o programa roda.
Stack trace
Rastro de chamadas e linhas que levou ao erro.
Warning
Aviso que merece atenção, mas não interrompe necessariamente a execução.

Três perguntas de diagnóstico

  1. O que a mensagem diz? Leia sem adivinhar.
  2. Em qual Script e linha começou? Clique na primeira linha relevante do seu código.
  3. Qual valor real chegou ali? Use um print temporário e typeof().
Não esconda erros de programação

pcall() existe para operações que podem falhar mesmo com código correto. Ele não corrige nome digitado errado, escopo incorreto ou nil inesperado. Será aplicado de verdade quando DataStore introduzir falhas externas.

Capítulo 2.9

Tipagem Luau, inferência, anotações e --!strict

Faça o editor verificar contratos antes que parte dos erros chegue ao teste.

Objetivos e vocabulário

Pré-requisitos: 2.1–2.8.

  • Distinguir tipo observado em execução de análise estática.
  • Usar inferência, anotações, alias e tipo opcional.
  • Ativar --!strict e interpretar avisos.
Inferência
Dedução automática de um tipo pelo analisador.
Anotação
Tipo escrito explicitamente após dois-pontos.
Alias de tipo
Nome reutilizável criado com type.
Tipo opcional
Valor que pode ser do tipo indicado ou nil, escrito com ?.
Refinamento
Informação mais precisa obtida após uma verificação.

Dois momentos diferentes

typeof(valor) roda durante a sessão e observa um valor real. O verificador estático examina o texto antes da execução. Ele ajuda a encontrar incompatibilidades, mas não prova que toda regra do jogo está correta nem torna dados recebidos confiáveis.

Anote contratos, não cada detalhe

A inferência já entende muitos locais. Anotações são especialmente úteis nos parâmetros, retornos e estruturas compartilhadas. Evite any como atalho: ele desliga verificações importantes naquele caminho.

type ConfiguracaoSala = {

	if tempoLimite == nil then
		return "Sem limite de tempo"
	end

	return `Limite: {tempoLimite} segundos`
end

local configuracao: ConfiguracaoSala = {

	tempoLimite = 60,

print(descreverTempo(configuracao.tempoLimite))

  3. Como experimento, envie "três" no lugar de 3. Observe o aviso antes de executar e restaure o número.
