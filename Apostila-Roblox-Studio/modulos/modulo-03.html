Capítulo 3.1

Propriedades, métodos, eventos e conexões

Diferencie estado, ação e sinal para reagir sem consultar o mundo em um laço constante.

Objetivos e pré-requisitos

Pré-requisitos: 1.2, 2.4, 2.6 e a avaliação do Módulo 2.

  • Distinguir propriedade, método e evento.
  • Conectar callback com :Connect() e receber o parâmetro do evento.
  • Evitar repetição acidental com debounce simples.
  • Reconhecer quando guardar e desconectar uma conexão.

O parâmetro é a BasePart que tocou o sensor: pode ser pé, acessório, peça solta ou veículo. Neste capítulo qualquer contato apenas muda uma cor. Identidade, personagem e estado por jogador serão validados depois de 4.1.

Crie um botão de contato com efeito temporário

Projeto
Primeira sala interativa
Objeto
BotaoEvento · Part
Script
EventoDoBotao · Script
Contexto
Servidor · quando houver contato
  1. Com o teste parado, em game → Workspace → Ambiente → PrimeiraSala, crie a Folder Interacoes.
  2. Dentro dela crie uma Part BotaoEvento. Defina Size = 6, 1, 6, Anchored = true, CanCollide = true, CanTouch = true e uma posição acessível.
  3. Em game → ServerScriptService, crie o Script EventoDoBotao com RunContext = Server.
EventoDoBotao.server.luauScript · ServerScriptService · servidor
local botao = workspace.Ambiente.PrimeiraSala.Interacoes.BotaoEvento

const COR_PRONTA = Color3.fromRGB(45, 170, 95)
const COR_ATIVA = Color3.fromRGB(245, 175, 45)
const TEMPO_DE_ESPERA = 1.5

local ocupado = false

local function aoTocar(outraParte)
	if ocupado then
		return
	end

	ocupado = true
	botao.Color = COR_ATIVA
	print("Contato recebido de:", outraParte:GetFullName())

	task.delay(TEMPO_DE_ESPERA, function()
		botao.Color = COR_PRONTA
		ocupado = false
		print("Botão pronto para novo contato.")
	end)
end

botao.Color = COR_PRONTA
local conexao = botao.Touched:Connect(aoTocar)
print("Conexão ativa?", conexao.Connected)

Leitura por blocos

  • As constantes guardam valores imutáveis de configuração.
  • ocupado é o debounce global: enquanto true, novos contatos retornam cedo.
  • aoTocar recebe a Part informada pelo evento.
  • task.delay() agenda a restauração sem bloquear o restante do Script.
  • Connect() devolve RBXScriptConnection; sua propriedade Connected confirma o estado.
  1. Use F5 e caminhe sobre o botão. A cor deve mudar, voltar após cerca de 1,5 segundo e o Output deve identificar a Part de contato.
  2. Permaneça ou pule sobre o botão. Vários sinais podem ocorrer, mas o efeito não deve reiniciar enquanto ocupado for true.
  3. Como experimento, adicione conexao:Disconnect() logo após o último print. Confirme que a conexão fica inativa e o toque deixa de responder; depois remova essa linha.
Resultado esperado

A sala reage ao início e agora também a um evento do mundo. O botão alterna entre verde e laranja sem empilhar efeitos.

Se falhar: confirme nomes e hierarquia, CanTouch, RunContext Server e se o personagem realmente encosta. Se a cor nunca voltar, procure erro dentro da função agendada. Stop restaura o estado editado; copie novamente o código para reiniciar.

Fácil

Intermediário

Faça o botão alternar também Material entre SmoothPlastic e Neon durante o efeito.

Desafiador

Projeto 2 concluído: a Primeira sala reage ao início e ao contato. Projeto 3 iniciado: duplique a Part como ObstaculoEvento e crie um efeito visual temporário com debounce. Não aplique dano nem tente descobrir jogador ainda.

Revisão

  • Distingo dado, ação e sinal.
  • Sei de onde vem o parâmetro do callback.
  • Consigo explicar o debounce.
  • Sei que conexões persistentes precisam de ciclo de vida consciente.
Gabarito comentado

Fácil: declare local contatosAceitos = 0 fora da função e incremente depois da guard clause.

Intermediário: defina botao.Material = Enum.Material.Neon ao ativar e restaure Enum.Material.SmoothPlastic no callback de task.delay.

Desafiador: após incrementar, use if contatosAceitos == 3 then conexao:Disconnect() end. Como a função referencia conexao, declare a variável antes e atribua a conexão depois.

Capítulo 3.2

Encontrar e criar Instances, atributos e tags

Construa objetos por código e separe configuração de comportamento.

Objetivos e termos

Pré-requisitos: 2.7 e 3.1.

  • Criar uma Instance e definir Parent depois de configurá-la.
  • Escolher entre caminho direto, FindFirstChild() e WaitForChild().
  • Percorrer filhos e descendentes.
  • Configurar objetos com atributos e agrupá-los por tag.
Instance
Unidade fundamental do DataModel: Part, Folder, Script e serviços são exemplos.
Filho
Objeto cujo Parent é o objeto atual.
Descendente
Qualquer objeto abaixo, mesmo várias camadas depois.
Atributo
Dado personalizado armazenado em uma Instance.
Tag
Rótulo que permite encontrar objetos relacionados sem depender da mesma pasta.

Três formas de procurar

FormaQuando usarRisco
raiz.Pasta.ObjetoEstrutura conhecida e já existenteErro imediato se algo faltar
raiz:FindFirstChild("Objeto")Existência opcional ou validaçãoRetorna nil; deve ser verificado
raiz:WaitForChild("Objeto")Objeto esperado que pode chegar depoisPode suspender indefinidamente sem limite

GetChildren() devolve somente a camada imediata. GetDescendants() devolve toda a subárvore. Não percorra o Workspace inteiro quando uma pasta ou tag menor resolve.

Configure antes de definir Parent

Uma Instance pode começar a participar do mundo assim que recebe Parent. Defina nome, tamanho, posição, atributos e tag antes de colocá-la na pasta final, reduzindo estados incompletos observáveis.

Crie e audite coletáveis configurados

Crie o Script com RunContext Server. Ele criará game → Workspace → Ambiente → PrimeiraSala → Coletaveis quando necessário.

PrepararColetaveis.server.luauScript · servidor
local CollectionService = game:GetService("CollectionService")
local raizDaSala = workspace.Ambiente.PrimeiraSala

const TAG_COLETAVEL = "Coletavel"
const RECOMPENSA_MAXIMA = 100

local pasta = raizDaSala:FindFirstChild("Coletaveis")

if pasta == nil then
	pasta = Instance.new("Folder")
	pasta.Name = "Coletaveis"
	pasta.Parent = raizDaSala
end

local function criarColetavel(nome, posicao, recompensa, cor)
	local coletavel = Instance.new("Part")
	coletavel.Name = nome
	coletavel.Shape = Enum.PartType.Ball
	coletavel.Size = Vector3.new(2, 2, 2)
	coletavel.Position = posicao
	coletavel.Color = cor
	coletavel.Anchored = true
	coletavel.CanCollide = false
	coletavel:SetAttribute("Reward", recompensa)
	CollectionService:AddTag(coletavel, TAG_COLETAVEL)
	coletavel.Parent = pasta
end

criarColetavel("MoedaA", Vector3.new(0, 4, 0), 5, Color3.fromRGB(255, 210, 40))
criarColetavel("MoedaB", Vector3.new(5, 4, 0), 10, Color3.fromRGB(80, 180, 255))

print("Filhos diretos:", #pasta:GetChildren())

for _, instancia in CollectionService:GetTagged(TAG_COLETAVEL) do
	local recompensa = instancia:GetAttribute("Reward")
	local dentroDaPasta = instancia:IsDescendantOf(pasta)
	local valorValido = typeof(recompensa) == "number"
		and recompensa > 0
		and recompensa <= RECOMPENSA_MAXIMA

	if not instancia:IsA("BasePart") then
		warn(instancia:GetFullName(), "não é uma BasePart.")
	elseif not dentroDaPasta then
		warn(instancia:GetFullName(), "está fora da pasta esperada.")
	elseif not valorValido then
		warn(instancia:GetFullName(), "possui Reward inválido.")
	else
		print("Coletável válido:", instancia.Name, recompensa)
	end
end

game:GetService() obtém o serviço existente. Instance.new() cria objetos. SetAttribute() mantém a recompensa junto do coletável; a tag descreve seu papel. A auditoria não confia apenas na tag: confirma classe, hierarquia, tipo e limite.

  1. Execute com F5. Espere dois filhos e dois logs “Coletável válido”.
  2. No Explorer da sessão, selecione uma moeda e confirme o atributo Reward e a tag Coletavel no Properties.
  3. Troque uma recompensa para -5. Execute e confirme o warning específico.
  4. Crie manualmente uma Folder, aplique a mesma tag e execute; a auditoria deve rejeitá-la por não ser BasePart.

Diagnóstico: se duplicar objetos, lembre que cada nova sessão começa do estado editado; duplicação dentro da mesma sessão indica que a função foi chamada mais de uma vez. Se pasta for nil depois do if, confira Parent e nome. Stop remove as Instances criadas em teste.

WaitForChild sem espera cega

No servidor desta prática, você mesmo cria a pasta, então FindFirstChild é suficiente. Quando um objeto esperado puder surgir depois, WaitForChild suspende a tarefa atual. Não o use para esconder erro de nome ou hierarquia. No futuro, cliente e replicação darão um contexto real para essa espera.

Exemplo conceitualNão substituir a prática
local objetoEsperado = pasta:WaitForChild("MoedaA")
print(objetoEsperado:GetFullName())

for _, descendente in pasta:GetDescendants() do
	print(descendente:GetFullName())
end

Capítulo 3.3

Vector3, CFrame, pivôs e transformações

Represente pontos, direções e orientações sem depender de coordenadas frágeis.

Objetivos e termos

Pré-requisitos: 1.3, 2.3 e 3.2.

  • Usar Vector3 para posição, deslocamento, distância e direção.
  • Usar CFrame para posição + orientação.
  • Converter um deslocamento local em transformação no mundo.
  • Mover Parts e Models pelo pivô.
Vetor
Três números X, Y e Z que podem representar ponto ou deslocamento.
Magnitude
Comprimento de um vetor.
Vetor unitário
Direção com comprimento 1.
CFrame
Coordinate frame: posição e rotação em uma transformação.
Pivô
Ponto e orientação usados como referência para mover ou girar um objeto.
Espaço local
Eixos relativos ao objeto; o mundo usa eixos globais.

Dois tipos, dois trabalhos

Vector3.new(0, 4, -6) pode ser uma posição ou um deslocamento; o contexto dá significado. CFrame carrega posição e orientação. O “frente” local de uma Part corresponde ao eixo Z negativo, então CFrame.new(0, 0, -6) significa seis studs à frente da referência.

Ordem importa

referencia * deslocamento aplica o deslocamento nos eixos da referência. Inverter a multiplicação produz outra transformação. Use ToWorldSpace() quando quiser tornar a intenção didática explícita.

Gire uma porta pelo pivô e posicione um marcador à frente

Projeto

  1. Em Workspace → Ambiente → PrimeiraSala → Interacoes, crie o Model PortaPivo. Dentro, crie a Part Folha, com Size = 6, 8, 1 e Anchored = true.
  2. Selecione o Model. Na ferramenta Pivot, entre em edição e mova o pivô para o centro da borda esquerda da folha; finalize a edição. A rotação usará esse ponto como dobradiça.
  3. Na mesma Folder, crie Parts ancoradas Referencia e MarcadorFrontal, ambas pequenas e afastadas da porta.

TransformacoesDaSala.server.luauScript · servidor
local interacoes = workspace.Ambiente.PrimeiraSala.Interacoes
local porta = interacoes.PortaPivo
local referencia = interacoes.Referencia
local marcador = interacoes.MarcadorFrontal

const DISTANCIA_A_FRENTE = 6
const ANGULO_DA_PORTA = -90

local deslocamentoLocal = CFrame.new(0, 0, -DISTANCIA_A_FRENTE)
local destinoDoMarcador = referencia.CFrame:ToWorldSpace(deslocamentoLocal)
marcador:PivotTo(destinoDoMarcador)

local deslocamento = marcador.Position - referencia.Position
print("Distância:", deslocamento.Magnitude)
print("Direção:", deslocamento.Unit)

local portaFechada = porta:GetPivot()
local rotacao = CFrame.fromEulerAnglesXYZ(0, math.rad(ANGULO_DA_PORTA), 0)
local portaAberta = portaFechada * rotacao

print("A porta abrirá em dois segundos.")
task.wait(2)
porta:PivotTo(portaAberta)

print("A porta fechará em dois segundos.")
task.wait(2)
porta:PivotTo(portaFechada)
print("Teste de transformação concluído.")

O marcador recebe um CFrame no mundo derivado dos eixos da referência. A subtração de posições produz deslocamento; Magnitude mede seis studs e Unit informa só a direção. O Model guarda dois pivôs e alterna com PivotTo().

  1. Gire Referencia no eixo Y antes do teste. O marcador deve continuar à frente dela, não no mesmo eixo global.
  2. Execute com F5. Observe marcador, distância e giro da porta pela borda.
  3. Se a porta girar pelo centro, use Stop e corrija o pivô no modo de edição; não compense com coordenadas aleatórias.

Erros comuns: graus passados sem math.rad, usar Position quando a rotação precisa ser preservada, e calcular Unit de vetor zero. Para reiniciar, Stop restaura os pivôs editados e posições originais.

Prática guiada · parte 1

Teste o caminho e abra uma porta suavemente

Objetos
OrigemRay, DestinoRay, ObstaculoTeste, VisualRay, PortaAnimada
Script
TesteDeCaminho
Contexto
Servidor · uma consulta no início
Resultado
linha vermelha/verde e porta
  1. Em Workspace → Ambiente → PrimeiraSala → Interacoes, crie cinco Parts com os nomes acima. Deixe todas Anchored.
  2. OrigemRay e DestinoRay: Size 1,1,1, separadas por cerca de 20 studs. Coloque ObstaculoTeste entre elas.
  3. VisualRay: CanCollide = false, CanTouch = false, CanQuery = false. PortaAnimada: tamanho semelhante a uma porta.
  4. Crie TesteDeCaminho em ServerScriptService com RunContext Server.
TesteDeCaminho.server.luauScript · servidor
local Workspace = game:GetService("Workspace")
local TweenService = game:GetService("TweenService")
local interacoes = Workspace.Ambiente.PrimeiraSala.Interacoes

local origem = interacoes.OrigemRay
local destino = interacoes.DestinoRay
local visual = interacoes.VisualRay
local porta = interacoes.PortaAnimada

local direcao = destino.Position - origem.Position
local distancia = direcao.Magnitude

if distancia <= 0 then
	warn("Origem e destino precisam estar em posições diferentes.")
	return
end

visual.Size = Vector3.new(0.15, 0.15, distancia)
visual.CFrame = CFrame.lookAt(origem.Position + (direcao / 2), destino.Position)

local parametros = RaycastParams.new()
parametros.FilterType = Enum.RaycastFilterType.Exclude
parametros.FilterDescendantsInstances = { origem, destino, visual, porta }
parametros.IgnoreWater = true

local resultado = Workspace:Raycast(origem.Position, direcao, parametros)

if resultado then
	visual.Color = Color3.fromRGB(235, 75, 75)
	warn("Caminho bloqueado por:", resultado.Instance:GetFullName())
	print("Distância até o impacto:", resultado.Distance)
	print("Normal da superfície:", resultado.Normal)
else
	visual.Color = Color3.fromRGB(55, 190, 105)
	print("Caminho livre. Abrindo a porta.")

	local portaAberta = porta.CFrame + Vector3.new(0, porta.Size.Y + 1, 0)
	local informacoes = TweenInfo.new(1, Enum.EasingStyle.Quad, Enum.EasingDirection.Out)
	local tween = TweenService:Create(porta, informacoes, { CFrame = portaAberta })
	tween:Play()
	tween.Completed:Wait()
	print("Animação concluída.")
end

A direção já contém sentido e distância. O filtro exclui objetos auxiliares para não acertarem a si mesmos. Resultado nil significa nenhum candidato elegível; um RaycastResult oferece Instance, Position, Distance, Normal e Material. O tween interpola CFrame da Part sem um laço manual.

  1. Execute com o obstáculo no meio: linha vermelha, warning e porta parada.
  2. Use Stop, mova o obstáculo para o lado e execute: linha verde e porta sobe suavemente.
  3. Defina ObstaculoTeste.CanQuery = false e repita; ele deixa de ser candidato ao raycast mesmo podendo continuar visível.

Se o resultado surpreender: imprima origem, direção e membros do filtro. A direção não é um ponto final. Se a linha parecer invertida, confirme o eixo longo Z e o ponto médio. Stop restaura a porta.

Prática guiada · parte 2

Consulte uma área e deduplique Models

  1. Em Interacoes, crie Folder AlvosSensor. Dentro, crie Models AlvoA e AlvoB, cada um com duas Parts ancoradas.
  2. Crie Part SensorArea ao redor dos alvos: Transparency 0.75, Anchored true, CanCollide/CanTouch/CanQuery false.
  3. Crie Script ConsultaDeArea em ServerScriptService, RunContext Server.
ConsultaDeArea.server.luauScript · servidor
local Workspace = game:GetService("Workspace")
local interacoes = Workspace.Ambiente.PrimeiraSala.Interacoes
local sensor = interacoes.SensorArea
local pastaDeAlvos = interacoes.AlvosSensor

local parametros = OverlapParams.new()
parametros.FilterType = Enum.RaycastFilterType.Include
parametros.FilterDescendantsInstances = { pastaDeAlvos }

local partes = Workspace:GetPartBoundsInBox(
	sensor.CFrame,
	sensor.Size,
	parametros
)

local modelosUnicos = {}

for _, parte in partes do
	local modelo = parte:FindFirstAncestorOfClass("Model")
	if modelo then
		modelosUnicos[modelo] = true
	end
end

local quantidade = 0
for modelo in modelosUnicos do
	quantidade += 1
	print("Model encontrado:", modelo:GetFullName())
end

print("Parts retornadas:", #partes)
print("Models únicos:", quantidade)

A consulta retorna Parts, não entidades lógicas. A tabela usa cada Model como chave e elimina repetições. O filtro Include restringe a busca à pasta de alvos; ambiente e sensor não poluem o resultado.

  1. Execute: espere quatro Parts e dois Models, se cada alvo tiver exatamente duas Parts dentro da caixa.
  2. Mova uma Part parcialmente para fora. Como a consulta usa caixas delimitadoras, observe o resultado e compare com a geometria visual.
  3. Mova AlvoB inteiro para fora e confirme um único Model.

Nota de precisão: GetPartBoundsInBox usa bounding boxes. Quando a geometria exata de uma Part-sensor for indispensável, GetPartsInPart é a alternativa atual. Escolha pelo requisito, não por hábito.

Exercícios e projeto

Fácil

Troque o filtro do raycast para Include e permita somente ObstaculoTeste; explique o resultado.

Intermediário

Anime simultaneamente CFrame, Transparency e Color da porta e restaure após dois segundos.

Desafiador

Faça três raycasts paralelos e considere livre somente se nenhum atingir obstáculo; visualize cada linha.

Incremento do Projeto 3: crie um sensor de área que lista Models únicos e um obstáculo visual animado. O sistema ainda não procura Humanoid nem aplica dano; isso conclui somente em 4.1.

Revisão e fechamento

  • Escolho contato, raio ou volume conforme a pergunta.
  • Sei que direção do raycast inclui distância.
  • Configuro filtros explicitamente.
  • Deduplifico Parts antes de tratá-las como uma entidade.
  • Uso TweenService para propriedades compatíveis.
Gabarito comentado

Fácil: use FilterType = Include e {interacoes.ObstaculoTeste}. Outros objetos deixam de ser candidatos.

Intermediário: a tabela de meta pode conter CFrame, Transparency e Color. Guarde valores originais e crie segundo tween para restaurar; evite tweens concorrentes na mesma propriedade.

Desafiador: desloque as três origens lateralmente, execute a mesma direção e guarde cada resultado. “Livre” é true apenas quando os três são nil. Crie uma Part visual por raio.
